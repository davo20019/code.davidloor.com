# v1.1 CSP Hardening — Nonce via HTMLRewriter

## Context

The v1 main-app CSP (served from `public/_headers`) uses `'unsafe-inline'` in `script-src` and `style-src` because Next.js static exports inline chunk manifests and critical CSS at build time.  This is acceptable for v1 but not ideal.  This document records the intended v1.1 upgrade path: replacing `'unsafe-inline'` with per-request nonces injected by a Cloudflare Worker using `HTMLRewriter`.

## Why nonces?

A strict CSP that omits `'unsafe-inline'` prevents XSS payloads from executing inline `<script>` or `<style>` blocks.  With nonces:

- Each response gets a unique random token (e.g., `crypto.getRandomValues` base64).
- The `Content-Security-Policy` header includes `'nonce-<token>'` in `script-src` and `style-src`.
- Every `<script>` and `<style>` element in the HTML is rewritten to carry that nonce via `HTMLRewriter`.
- The browser only executes scripts/styles whose `nonce` attribute matches the header value.
- Inline event handlers (`onclick=…`) and `javascript:` URIs are still blocked.

## Architecture

### v1 (current)

```
Cloudflare Workers Static Assets
  └── serves Next.js static export verbatim
  └── _headers file adds CSP with 'unsafe-inline'
```

### v1.1 (planned)

```
Cloudflare Worker (thin proxy)
  └── fetches static asset from ASSETS binding (same Workers Static Assets bucket)
  └── generates nonce = crypto.randomUUID() or 16-byte base64
  └── HTMLRewriter transforms <script> and <style> → adds nonce attribute
  └── rewrites Content-Security-Policy header:
        script-src 'self' 'nonce-<token>'
        style-src  'self' 'nonce-<token>'
```

No `'unsafe-inline'` appears in the v1.1 header.

## Implementation sketch

```ts
// worker/main.ts  (v1.1 entry point — replaces pure static-asset mode)

export default {
  async fetch(request: Request, env: { ASSETS: Fetcher }): Promise<Response> {
    const nonce = btoa(String.fromCharCode(...crypto.getRandomValues(new Uint8Array(16))));

    const assetResponse = await env.ASSETS.fetch(request);

    const contentType = assetResponse.headers.get("content-type") ?? "";
    if (!contentType.includes("text/html")) {
      // Non-HTML assets: pass through unchanged.
      return assetResponse;
    }

    const csp = [
      "default-src 'self'",
      `script-src 'self' 'nonce-${nonce}'`,
      `style-src 'self' 'nonce-${nonce}'`,
      "img-src 'self' data:",
      "frame-src https://runner.code.davidloor.com",
      "connect-src 'self'",
      "base-uri 'none'",
      "form-action 'self'",
    ].join("; ");

    const response = new Response(assetResponse.body, assetResponse);
    response.headers.set("Content-Security-Policy", csp);

    return new HTMLRewriter()
      .on("script", new NonceRewriter(nonce))
      .on("style", new NonceRewriter(nonce))
      .transform(response);
  },
};

class NonceRewriter implements HTMLRewriterElementContentHandlers {
  constructor(private nonce: string) {}
  element(el: Element) {
    el.setAttribute("nonce", this.nonce);
  }
}
```

## Caveats

1. **Build output must be inspectable**: the nonce attribute injected by HTMLRewriter appears at response time, not build time.  CSP reports (`report-uri` / `report-to`) should be enabled to catch any missed inline blocks.
2. **`'strict-dynamic'`**: combining `'nonce-<token>'` with `'strict-dynamic'` allows nonce-carrying scripts to load further scripts dynamically (e.g., Webpack chunks loaded via `<script>`) without needing `'self'` in `script-src`.  This is the recommended pairing in Google's strict CSP guide.
3. **Runner subdomain**: the `runner.code.davidloor.com` CSP already omits `'unsafe-inline'` (only `'unsafe-eval'` and `'wasm-unsafe-eval'` are present); no change needed there.
4. **Cost**: switching from pure static assets to a Worker proxy adds ~1 ms of CPU per HTML request.  For a low-traffic interview-prep site this is negligible.

## Migration steps (when ready)

1. Add `worker/main.ts` (as above) to the repo.
2. Update `wrangler.toml`: change from `assets = { directory = "./out" }` to a Worker entry point that holds the ASSETS binding.
3. Remove `'unsafe-inline'` from `public/_headers` (the Worker's dynamic header will replace it).
4. Deploy to a preview URL; smoke-test with browser DevTools → Network → check CSP header.
5. Open browser console on the preview and confirm zero CSP violation reports.
6. Promote to production.
